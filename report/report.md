- Every proof starts from the **all-zero register state** and counts only after reset has been
  asserted and released (`vf_armed`). Registers listed under *Lint: registers without reset* power up
  unknown in silicon; the model starts them at 0, which is an assumption, not a proof.
- Inputs are unconstrained except by the listed assumptions. In particular, memory read data is free
  unless a memory model is listed — control and address properties must hold for ANY data; arithmetic
  claims need a memory model.
- A *bounded* result (`holds_within N`) says nothing past cycle N.
- A *liveness* claim ("eventually completes") is checked as a bounded response: it holds only under
  the stated assumptions and within the stated bound.
- Formal results do not establish timing closure, and do not prove that the written specification is
  the intended one.

### Counterexample — `c4_write_addr_in_range`

Result writes share one registered SRAM address with three reads (next butterfly A, operand B,
twiddle), and the write has the lowest priority in that mux while its strobe is raised on
pipeline_valid[4] alone. A result therefore goes out with whichever read address won that cycle —
in a counterexample, the twiddle-read address 0x1000, i.e. into the twiddle bank. Neither CTRL.reset
nor the block reset flushes the pipeline (pipeline_valid and the pipeline address/data registers have
no reset), so in-flight writes go out after the engine is idle or after reset is released.

## Covers (non-vacuity)

A cover that is reached shows the assumptions still allow that behaviour; an unreachable cover means either the assumptions are too strong or the logic is dead.

| id | statement | result | expected | status | at cycle |
|---|---|---|---|---|---|
| `cov_done_any` | A run completes (any programmed length). | reached | reached | as-expected | 9 |
| `cov_done_legal` | A run of a legal length completes under the software assumptions. | reached | reached | as-expected | 1044 |
| `cov_done_legal_no_abort` | A run of a legal length completes with no abort. | undecided | undecided | as-expected |  |
| `cov_error` | The engine reports an error. | unreachable | unreachable | FINDING |  |
| `cov_rescale` | Rescaling becomes active. | reached | reached | as-expected | 20 |
| `cov_twiddle_load` | Software loads a twiddle word over APB. | reached | reached | as-expected | 4 |
| `cov_tl_write_ack` | A TL-UL write is acknowledged. | reached | reached | as-expected | 5 |
| `cov_tl_read_data` | A TL-UL read returns data. | reached | reached | as-expected | 5 |

**`cov_error`:** Dead logic: the RUN -> ERROR transition is guarded by fft_error_o, which is itself decoded from the
ERROR state, so the engine can never enter ERROR. FFT_STATUS.error and the fft_error_o interrupt are
constant 0 — proved for every input sequence.

## Run it yourself with the Vyges CLI

Install the CLI, then the physical engines — `vyges-formal` and the `vyges-lec` prover ship there:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/vyges-tools/cli/releases/latest/download/vyges-installer.sh | sh
# or: brew install vyges/tap/vyges
vyges install physical
```

A campaign also needs [Yosys](https://github.com/YosysHQ/yosys) and [Verilator](https://github.com/verilator/verilator) on `PATH`, and the Liberty the manifest names (`--liberty FILE` overrides it).

```sh
vyges formal run manifest.toml --out out-soc          # prove, replay, mutate, report
vyges formal replay manifest.toml <id> --out out-soc --show <signal,...>   # one counterexample, cycle by cycle
vyges formal report manifest.toml --out out-soc       # re-render after editing expectations
```

The manifest names the RTL (a git repository and its files), the monitors and the module each binds into, and every assumption, property, cover and mutant. `vyges formal --help` lists every option. Exit status: 0 when every result is as expected, 2 when anything is not, 1 on a tool error.
