## Limits of these results

- Results hold only for the RTL commit, parameters, defines and monitors listed under *Scope*, as
  elaborated and synthesized by the tool versions listed there.
- Every proof starts from the **all-zero register state** and counts only after reset has been
  asserted and released (`vf_armed`). Registers listed under *Lint: registers without reset* power up
  unknown in silicon; the model starts them at 0, which is an assumption, not a proof.
- Inputs are unconstrained except by the listed assumptions. In particular, memory read data is free
  unless a memory model is listed — control and address properties must hold for ANY data; arithmetic
  claims need a memory model.
- A *bounded* result (`holds_within N`) says nothing past cycle N.
- A *liveness* claim ("eventually completes") is checked as a bounded response: it holds only under
  the stated assumptions and within the stated bound.
- Formal results do not establish timing closure, and do not prove that the written specification is
  the intended one.

Configuration: FFT_MAX_LENGTH_LOG2 = 10, data and twiddle width 16, FFT_USE_SRAM_MACRO with the SoC's
two-bank SRAM bridge (models/fft_data_sram.v), APB on the core clock and reset, AXI port tied off
(models/fft_formal_top.v). APB inputs and SRAM read data are unconstrained: every claim here is a
control, address, status or interrupt claim that must hold for any bus activity and any data. The
TL-UL bridge of the SoC campaign is not part of the IP and is not under proof here. End-to-end
numerical correctness is covered by the IP's golden-model regression, not by these proofs.

## Run it yourself with the Vyges CLI

Install the CLI, then the physical engines — `vyges-formal` and the `vyges-lec` prover ship there:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/vyges-tools/cli/releases/latest/download/vyges-installer.sh | sh
# or: brew install vyges/tap/vyges
vyges install physical
```

A campaign also needs [Yosys](https://github.com/YosysHQ/yosys) and [Verilator](https://github.com/verilator/verilator) on `PATH`, and the Liberty the manifest names (`--liberty FILE` overrides it).

```sh
vyges formal run manifest.toml --out formal-out          # prove, replay, mutate, report
vyges formal replay manifest.toml <id> --out formal-out --show <signal,...>   # one counterexample, cycle by cycle
vyges formal report manifest.toml --out formal-out       # re-render after editing expectations
```

The manifest names the RTL (a git repository and its files), the monitors and the module each binds into, and every assumption, property, cover and mutant. `vyges formal --help` lists every option. Exit status: 0 when every result is as expected, 2 when anything is not, 1 on a tool error.
